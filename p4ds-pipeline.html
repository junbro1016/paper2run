§ 01

진입점과 캐싱

세 개의 엔드포인트로 시작한다. 모든 업로드는 SHA-256으로 해싱되어 동일 논문 재추출을 방지한다.

1
PDF 업로드
POST /papers/extract · /papers/figures/extract · /paper2run/run
세 개의 엔드포인트가 각각 수식, 그림, 풀파이프라인 작업을 트리거한다. 모두 동일하게 PDF 파일을 multipart로 받는다.
2
해시 기반 캐시 조회
find_cached_paper(filename, file_hash)
파일 내용의 SHA-256을 계산해 동일 논문이 이미 처리됐는지 확인. 파일명이 달라도 내용이 같으면 캐시 hit. ?force=true 쿼리로 우회 가능.
3
분기 — BackgroundTask 또는 즉시 반환
캐시 hit이면 job done으로 즉시 반환. 아니면 백그라운드 작업으로 진행하고 job_id 반환 — 클라이언트는 폴링으로 상태 확인.
§ 02

수식 추출

Vision API로 페이지마다 후보 수식을 뽑고, 강화된 시그니처로 중복을 제거한 뒤 LLM으로 핵심만 3~8개로 압축한다.

1
PDF → 페이지 이미지 (generator)
pdf_to_images() · DPI=150
한 페이지씩 yield하고 Pixmap을 즉시 해제. 메모리를 1페이지분으로 유지해 Render 512MB 환경에서도 안전.
2
페이지별 수식 후보 추출
extract_equations_from_page() · Vision API
페이지당 최대 8개 후보. 시스템 프롬프트가 hallucination 금지, 표기 보존, 불확실 시 ? 마킹을 강제한다. 출력 필드:
  • latex · equation_number · description · context
  • section_hint · is_display_equation · is_numbered
  • likely_background · confidence
3
강화 시그니처 중복 제거
dedup_equations()
\begin{equation} 래퍼, \label, \tag, \left/\right, \mathcal{X}를 정규화한 후 비교. 표기 다양성으로 인한 false split을 막는다.
4
핵심 수식 필터 — 2단 전략
filter_core_equations()
후보가 ≤ 30개면 single LLM 호출, > 30개면 batch 25개씩 1차 필터 → 최종 merge filter.
  • role 분류: model · loss · update · inference · definition
  • importance_hint, core_reason, keep_rank를 함께 부여
5
Supabase 저장 — 최종 3~8개
save_to_supabase()
file_hash로 기존 paper를 찾고 없으면 upsert. equations 테이블은 paper_id로 delete 후 insert.
§ 03

그림 추출 2-Pass

먼저 후보를 다 모으고, 텍스트 메타데이터만으로 LLM에게 핵심을 고르게 한 뒤, 선택된 것만 고해상도로 정밀 크롭한다.

Pass 1 — 후보 수집
1
페이지별 figure 감지
detect_figures_on_page() · DPI=120 · Vision API
architecture / pipeline / process / conceptual 다이어그램만 수집. 테이블·샘플 그리드·loss 커브·ablation은 제외.
  • 페이지당 최대 2개, confidence ≥ 0.6
  • 반환: figure_body_bbox + caption_bbox + crop_bbox
  • _parse_fig_id(caption)로 fig1, fig2 번호 파싱
Pass 2 — LLM 선택
2
핵심 그림 선택 (텍스트만)
select_key_figures(title, candidates, max=3)
이미지를 전송하지 않고 메타데이터만 보냄 — 비용 절약. 우선순위:
  • ① 메인 architecture 다이어그램
  • ② 핵심 process diagram
  • ③ 핵심 sub-component diagram
Pass 3 — 고품질 크롭
3
정밀 bbox 크롭
high_res_crop() · DPI=250
좌·우·상단은 crop_bbox를 우선하되 body/caption bbox와 union해 LLM이 좁혀도 잘림을 막는다. 하단은 fitz로 텍스트 라인을 스캔해 캡션의 마지막 줄을 정확히 찾아낸다 — _find_caption_bottom_pt().
  • "Figure N" / "Algorithm N" 패턴 매칭
  • Continuation 4중 검사: x-overlap, 줄 간격(line height × 1.6), section heading 경계, LLM cap_y1 + 15pt
  • 여백: 좌·우·위 10pt, 아래 8pt
4
Supabase Storage 업로드
upload_figure_to_storage() → save_figures_to_supabase()
크롭 실패 시 fallback으로 PDF 재렌더 후 저해상도 크롭 — 빈 이미지가 나오지 않도록 보장.
§ 04

Paper2Run 풀파이프라인

LangGraph로 오케스트레이션되는 5단계. flagged 비율이 높으면 planner로 한 번 되돌아간다.

profiler
pdf_text를 분석해 paper_type, difficulty 등 메타 프로파일 생성
↓
planner
profile 기반으로 추출 계획 수립 — 어떤 extractor를 우선할지 결정
↓
extractor · dispatcher
계획에 따라 4개 추출기로 분기 · 수식과 그림은 §2, §3 파이프라인 재사용
equation_extractor
figure_extractor
algorithm_extractor
command_extractor
↓
grounding
추출물을 GitHub repo의 코드 청크와 매칭. verification_status: verified / weak / no_match / hallucinated
↺
flagged 비율이 ≥ 30%이고 replan < 1이면 planner로 회귀 — 최대 1회.
§ 05

데이터 흐름

클라이언트 → FastAPI → Vision API / PyMuPDF → Supabase. 동기적인 응답은 job_id만, 무거운 일은 백그라운드로.

CLIENT · WEB
업로드 & 폴링
  • multipart upload
  • 받음 → job_id
  • 5초 간격 폴링
  • done → 결과 조회
API · FASTAPI
오케스트레이션
  • SHA-256 해시
  • cache lookup
  • BackgroundTask
  • Vision API 호출
  • PyMuPDF 렌더링
STORAGE · SUPABASE
영속 계층
  • papers
  • equations
  • figures
  • storage/bucket
§ 06

안정성 장치 & 핵심 API

제약된 환경(Render 512MB, free tier sleep)에서 견디기 위한 설계 결정과, 클라이언트가 알아야 할 핵심 엔드포인트.

Memory
pdf_to_images generator + pix=None 즉시 해제로 Render 512MB OOM 방지.
중복 감지
파일 내용 SHA-256 해시로 동일 논문 / 다른 파일명을 잡아낸다.
LaTeX dedup
wrapper, label, tag, mathcal 정규화 시그니처로 표기 차이를 무시.
큰 후보셋
30개 초과 시 batch 25개씩 1차 필터 → 최종 merge filter.
그림 크롭
fitz line-level 캡션 탐색으로 본문 침범을 막는다.
잘림 방지
crop_bbox + body/caption bbox union으로 LLM이 좁혀도 보정.
Fallback
high_res_crop 실패 시 PDF 재렌더 후 저해상도 크롭 — 빈 이미지 없음.
